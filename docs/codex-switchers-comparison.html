Build a handoff tool, not a router

The best fit is the smallest product that changes the official Desktop login deliberately and can explain every failure.

Recommended design

A local, manual close → preserve → switch → reopen utility. Encrypt inactive credentials, use the official runtime for login, journal writes, and keep actual Desktop confirmation separate from file installation.

Closest product contract

liuzhao1225/codex-account-switcher

Native Windows/macOS handoff with a small auth-only boundary. Keep the ordered lifecycle; replace plaintext saved sessions and bounded-only restoration with a protected vault and crash journal.

Narrow core reference

JJLiebig/codex-account-switcher

Rust, a small declared file set and separate Windows/WSL state. Keep scope discipline; do not copy force switching or quota-window priming.

Inactive credential storage

Symbioose/claude-account-switcher

Its Codex support uses macOS Keychain for inactive accounts and acknowledges file-backend limitations. Borrow the secret-storage boundary, not automatic file-mode configuration.

Profile isolation alternative

burakdede/aisw

Managed per-account CODEX_HOME is attractive for CLI isolation. Treat Desktop environment propagation and local-state behavior as an unproven adapter, not a shortcut.

Two facts change the design

OpenAI’s account-switching help currently excludes Codex desktop. Its authentication documentation also supports file and credential-store modes; an existing auth.json does not establish which backend is authoritative. O1 O2 O4

A separate official app-server helper can inspect an account, but that is not a verified observation of the reopened Desktop instance. Our status model must preserve that distinction. O3 C1

These are design references, not installation endorsements

Feature fit does not establish credential safety. Source availability makes review possible; self-building still trusts the source, dependencies, compiler, OS and official Codex runtime. No product here received a full security audit.

Comparison method and boundaries

“Best” here means closest to a locally controlled Codex Desktop handoff, not most stars or most features.

FamilyWhat it changesWhy it matters
Cold handoffStops affected clients, swaps the live authentication state, then reopens the official app.Closest to the request. Quiescence, latest-token capture, crash recovery and post-launch identity are the hard parts.
File/profile CLICopies or selects saved auth; may expect the user to restart clients.Useful small code references, but a terminal account switch is not proof of Desktop lifecycle control.
Isolated account homesLaunches each account with a separate CODEX_HOME.Avoids a shared auth slot only when the real launch path honors it. History/settings and child-process behavior require separate review.
Proxy/routerRoutes requests through a local or remote gateway and picks outbound credentials.Can leave the UI logged into account A while inference uses account B. This is a different product and data boundary.

Selection criteria

Priority is actual Desktop lifecycle support, narrow credential mutation, secure inactive storage, preservation of refreshed sessions, deterministic recovery, policy-aware identity handling and a small build/runtime surface. We did not award numerical security scores from marketing claims.

Evidence depth

All 36 comparison entries have a reviewed README or project document. One leading candidate also has a pinned source spot-check of its switch coordinator and a partial read of its runtime adapter. The additional 16 names are repository-search leads only and are not ranked. A repository entry is not proof of an independently developed codebase.

No third-party program was installed; no real credential was entered; no packaged binary was compared with source; no cross-platform runtime behavior, timing or security guarantee was independently tested. Releases, licenses, maintenance activity and full test suites were not uniformly audited. A platform label records the project’s documented surface, not our certification.

Names that are easy to confuse

lizhelang/codexbar is not steipete/CodexBar. atuizz/codex-dock is not lxl8800/codex-dock. Sls0n/codex-account-switcher uses the package name codex-auth, but is not Loongphy/codex-auth. The former xtftbwvfp/codex-switcher URL resolves to VallierDev/codex-switcher and is counted once.

What our implementation should learn

Use existing work to discover failure modes, not as implicit authority to copy its scope.

AdoptDo not copyResulting spec contract
Ordered close/save/install/reopenFile-copy success presented as Desktop identity proofSeparate installed, accepted, launched and confirmed states.
Keep the mutation set smallCopying entire homes, SQLite state, hooks or configurationExact-version auth resource allowlist; zero workspace migration.
Secure inactive account storagePlaintext backup/export trees or silent file-mode downgradeEncrypted vault plus native protected key; active plaintext disclosed.
Preserve current auth before leavingReplaying a stale first-login refresh tokenImmutable current generations; capture after every legitimate official refresh.
Native app/tray UXAgent/MCP/HTTP authority over credentialsIntent-only renderer, native confirmation and backend validation.
Recovery diagnosticsOptimistic “all done” after a partial multi-file writeEncrypted write-ahead journal and conservative reconciliation.
Explicit user choiceAutomatic quota rotation, prompt warm-ups, provider fallbackNo model calls, hidden account changes or inference proxy.

The strongest alternative is isolation, not hot-swapping

A separate account home can be cleaner for a managed CLI launch. It becomes a Desktop solution only after proving the actual application launch, child processes and state behavior. v0.1.0 therefore uses an explicitly qualified cold handoff rather than claiming portable Desktop isolation.

These are design judgments based on the catalog, not claims that any listed project is malicious. See the specification for the exact safety and acceptance contracts.
